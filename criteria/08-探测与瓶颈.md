## 探测顺序按「信息增益 ÷ 代价」排，不按「已知信息的先后」排

<!-- 原编号 §2.141 · 脱敏风险 低 -->

**问题**：调查一批待确认事实时，不同探测手段的耗时差异很大。一条命令可能只需极短时间，而反汇编可能需要数十秒；如果按照已有认知或熟悉程度安排顺序，就可能提前执行高代价手段。

**机制**：以「信息增益 ÷ 代价」衡量探测手段，对事实清单中的每项标注最便宜的探测手段，再按代价从低到高执行。较便宜的探测已经取得证据时即可停止；只有其结果为 unknown 时，才启用昂贵手段。该规则用于调查阶段的探针排序；优化阶段定位热点则采用分段计时。最昂贵的探测步骤在 90% 的场合都不必执行，这也体现了下沉边界。

**证据**：实测（两种工具对同一目标）：构建信息分析耗时较长 ⇒ 轻量版本元信息查询耗时极短｜可执行文件概览耗时数秒 ⇒ 格式概览、动态加载信息与符号查询耗时极短｜打包应用分析失败 → 耗时数十秒、产生数百兆体积的 JSON；资源提取与全量文本检索耗时数秒、产生较小体积的结果。

**判据**：① 列事实清单时，给每条标「最便宜的探测手段」；② 按代价升序跑，拿到证据就停；③ 昂贵手段只在「便宜手段给了 unknown」时启用——不是“反正能跑，跑一遍更保险”。

**脱敏说明**：已剔除具体日期及精确耗时与容量读数，全部转换为相对量级表述，机制、判据逻辑及边界说明语义完整保留，未引入任何新增结论。

## 调用轮次比字节成本更高：将独立探针合并为单次调用

<!-- 原编号 §2.142 · 脱敏风险 低 -->

**问题**：执行一次工具调用时，其固定开销（包含模型推理与上下文重复读取）通常远大于该次调用返回的数 KB 数据量。因此，将任务拆分为多次独立的小调用，其总成本往往高于合并为一次包含多任务的大调用。

**机制**：将相互独立的探针任务通过串接的方式合并为单次执行调用，利用分隔标记来区分不同探针的输出区域，并强制对每个探针的输出数据量设置上限进行截断，以防止单次调用产生过量数据。

**证据**：实际优化验证中，目标调用次数设定为 2–4 次：即先执行一次批量侦察，随后进行一到两次定向切片探查，最后作答。对于已经确认获取的信息，不再进行重复验证。

**判据**：① 当前步骤与后续步骤是否可以合并为单次调用？若可以则必须合并；② 每个探针的输出必须设定明确的数量上限（否则单次调用导致上下文过载，其成本将高于多次独立调用）；③ 停止探查的判定条件是“被查询的每一个项目均已获得确凿证据”，而非“查询过程感觉已经充分”。反例边界：批量合并仅适用于完全独立的探针。存在依赖关系的任务（即后一条探查需要依赖前一条探查的结果）绝对不能合并，否则会导致错误指向自身或引发执行语法错误。

**脱敏说明**：原文仅包含通用的技术优化逻辑与调用次数目标，已剔除所有具体项目名称、内部代号及特定命令细节，剩余内容为通用的工程调用优化经验，无法反推出特定组织或项目的内部信息。

## 字段名会骗人：先打印形状，再写消费代码

<!-- 原编号 §2.168 · 脱敏风险 低 -->

**问题**：接入一个返回百余 KB 量级 JSON 的内容读取接口时，字段名看起来足以说明数据用途，但四个字段的实际序列化形状都与按名称作出的预期不符。若直接按字段名编写消费代码，容易把字符串当数组、把对象当列表，或把嵌套对象直接传给只接受字符串的文本节点。

**机制**：字段名描述的是业务意图，不是序列化形状。同一份 API 中可能混用数组、对象和字符串，因为服务端不同位置由不同人员分别拼装；字段名本身不会说明某一层究竟是 list、dict 还是 str。该规则用于取得跨系统字段的形状事实，不替代结论分级或跨脚本隐式契约的检查。

**证据**：一次接口响应实测中，响应体为百余 KB 量级 JSON，四个字段同时与名称预期不符：选项字段本应是“每项一个选项”的数组，实测却是用换行符拼接的字符串（"A. …\nB. …\nC. …\nD. …"），且一行里常塞两个选项；答案字段本应是选项文本，实测只是字母 D；词表字段本应包含词条，实测恒为空列表；长难句分析字段本应是数组，实测却是单个 dict，其中定位信息又是包含段落索引和句子索引的 dict，而不是字符串。后果是按换行符拆分选项时只拆出不足半数条目，只有开头的字母被渲染为选项标记，后两个字母作为纯文字留在文本中；把定位对象直接传给文本节点则报 text must be string。这些形状来自对单个已认证订单对象的本地实测，同一 API 的其他内容类型未逐一验证，切换内容类型后必须重新打印确认。

**判据**：以下任一情况即算违规：① 要使用的字段尚未先打印类型、长度和一条样例（type(v).__name__、len(v)、repr(v)[:200]），就开始写消费代码；或凭字段名推断容器类型。② 嵌套深度 ≥2 层的字段没有逐层打印键名（list(dict)[:12]），因而可能漏掉某一层实际是 dict 而不是 list。③ 发现某个字段的形状与预期不符后，没有立刻把同批字段全部打印一遍。④ 形状校验没有通过 isinstance 断言落入代码，只是在探索时临时查看一次。

**脱敏说明**：已将具体日期、精确容量和精确计数替换为相对量，未改动判据逻辑与机制描述，指纹残留风险低。

## 内容主站被反爬拦截时，先查同内容的 CDN/渲染旁路，别急着放弃或启用重型浏览器自动化

<!-- 原编号 §2.205 · 脱敏风险 低 -->

**问题**：抓取被 403 或挑战页挡住时，容易得出“抓不到”的结论，或立即启用浏览器自动化这类重型方案。但许多站点的内容分发域与主站域采用不同策略：主站启用了边缘防护，CDN 或静态域可能直接放行。

**机制**：先枚举承载同一内容的替代域（CDN/API/embed），换域重试一次；若渲染页无法直接提供源码，则检查“转义载体”，如 `srcdoc=`、`data:` URL、`__NEXT_DATA__`，解开一层转义后获取全文。抽取器按“取最长实质块”编写，跳过 console 垫片和 analytics 埋点，并保留“全量数 vs 抽到数”进行对账。

**证据**：测试了一批代码作品页面：主站作品地址使用命令行 HTTP 客户端和无头浏览器均返回 403 挑战页；改用同一内容服务的 CDN 全页地址后可直接放行，返回页把整份作品文档放入 `<iframe id="result" srcdoc="…">`（HTML 转义）中，经 `html.unescape` 解转义后得到完整文档，可直接抽取 `<style>`、`<script>`、`<body>`。19/19 全部成功，抽取器为数十行。

**判据**：① 主站返回 403 不等于内容不可得：先枚举承载同一内容的替代域（CDN/API/embed），换域重试一次，再考虑浏览器自动化；② 渲染页拿不到源码时，检查“转义载体”：`srcdoc=`、`data:` URL、`__NEXT_DATA__`，解开一层转义即可获取全文；③ 抽取脚本按“取最长实质块”编写，跳过 console 垫片/analytics，并保留“全量数 vs 抽到数”进行对账。

**脱敏说明**：具体日期、页面容量数与行数均已替换为相对量或删除；保留的 19/19 为判据证据所需的小样本比值，403 为机制状态码，不构成可唯一定位单次执行的读数指纹。

## 「改了尺寸却没生效」类渲染 bug：先做零成本 grep 分诊，再谈断点

<!-- 原编号 §2.206 · 脱敏风险 低 -->

**问题**：在图形渲染场景中，画面「只画进一小块」，这种现象极易被误诊为着色器数学计算错误或布局 CSS 问题。

**机制**：在尺寸调整逻辑（如 resize 函数）中修改了画布的宽高属性（canvas.width/height），但遗漏了对 WebGL 视口接口 gl.viewport(...) 的调用。由于 WebGL 默认视口尺寸即为画布元素的默认尺寸，导致画面被限制在默认的小区域内。该缺陷只需一行代码即可修复。

**证据**：实测：画面渲染结果缩在左下角约 300×150 的一块区域内。在本轮统计的案例中，约一成多「疑似」该问题，确认为 Canvas2D 误报。

**判据**：① 执行双条件 grep 分诊：若源码中 canvas.(width|height)= 有命中，而 .viewport( 零命中，则判定为触发此缺陷；② 300×150（或其 dpr 倍数）是「视口未同步」的指纹尺寸，若渲染残块尺寸与此对上，则直接排查视口设置；③ 适用域严格限制在 WebGL，Canvas2D 没有视口概念，必须先确认上下文类型再下结论，避免误判。

**脱敏说明**：日期与案例容量/疑似数配对（22/3）已转相对量「约一成多」；300×150 为浏览器默认画布尺寸这一通用常量，属判据引用特征，非某次执行的唯一读数，不构成来源指纹。

## 逆推黑箱模型：先读其自述规则，再按题型逐类采样

<!-- 原编号 §2.359 · 脱敏风险 低 -->

**问题**：当一个黑箱能力仅向外部提供名称、一句描述等元信息，不公开其内部提示词时，如何逆推出它实际遵循的判定规则。

**机制**：核心思路：先检查该黑箱是否将自身推理过程暴露出来；若暴露，则直接阅读其思维链，从它自己的推理中读取规则，而非猜测提示词。具体分五步：1. 判定可见面：若其展示思考过程，则读思维链；若未展示，则退回输入-输出差分，即同一问题更换约束运行两次，仅比对变化项。2. 一次一类题型：按题型类别依次采样，如从零提案、深色低对比诊断、多色编码等，只有切换题型才可能获得新判据，同题型重跑仅反映抽样波动。3. 停止判据：每轮须判断是否给出了新的可计算判据；当某轮仅产出「判据本身不可满足」这类结构性结论，或新增内容只剩句式变体时，即停止采样，不为凑轮数继续。4. 每条落成可复算式：采到的判据必须能写成可计算的量，如阈值、度数、比值、间距等，形容词与「要克制」一类表述不进入结论。5. 证据分级：seen 指由黑箱自己算出的数值；inferred 指从其选择反推的规则。两者不可混写。

**证据**：同一日进行三轮采样，读数均由黑箱自身计算。第1轮：辅色 #7C8F82 对米白为 3.00:1，被黑箱自行否定，改为 #5A6B60 后为 4.95:1 才保留；辅色压墨绿为 2.17:1，记为禁用；琥珀 #C1712F 为 3.23:1，仅够大字。第2轮（深色低对比诊断）：给出四个数值，主色 1.61:1、次色 2.07:1、点缀色 3.24:1，四色色相集中在 14.8° 区间（分别为 217.5、207.6、206.9、202.7），HSL 明度台阶为 14.5、6.0、9.3，饱和度分别为 22、67、62、52，顺序颠倒；并给出反算式：近黑底上图形需 3:1，相对亮度 L ≥ 0.11656；正文需 4.5:1，L ≥ 0.19987，而最亮点的实际亮度仅为 0.1299。第3轮（多色编码）：尝试主色绛红 #b01e3c（351.5°）与琥珀 35° 组合，色相差为 43.5°，刚超出允许区间；随后将主色压深至 #b45309（26°，5.06:1 可读），色相差回落至 38.3°，黑箱据此判定存在结构冲突。三轮后停止采样。

**判据**：该黑箱是否暴露了推理过程？若暴露，则不必猜测提示词，应先阅读其自身推理，再抽取规则表。每轮采样所切换的是题型还是仅措辞不同？本轮是否带来了新的可计算判据，若没有则应停止，不得以采样轮数充作工作量。所采集到的每条规则能否写成一个可复算的式子，例如阈值、度数或比值，还是仅含形容词？哪些数值由黑箱自行计算（seen），哪些由采样方推断（inferred），需明确区分。

**脱敏说明**：已移除具体产品名、内部路径与章节引用，实测数字均为通用颜色与对比度读数，不指向特定内部项目，技术逻辑本身为通用方法，难以反推内部信息。

## 生成式量具的输出自相矛盾时的裁决机制：依赖独立第三路，⛔ 禁止模型输出互证

<!-- 原编号 §2.228 · 脱敏风险 低 -->

**问题**：在音频数据处理任务中，针对同一音频，同一生成式语音识别模型在三种不同的输入范围下产生了三种不同的结果。若使用其中一次输出去裁决另一次，会导致基于虚假结果的错误处理，而真实缺陷在常规输入下可能被漏报，需通过特定的输入范围才能检出。

**机制**：生成式量具（如 ASR 或 LLM 判定）依赖语言先验对输入进行补全，其输出是「最符合逻辑的文本」而非客观测量值。当输入范围发生变化时，先验语境随之改变：整文件输入存在重复抑制现象，短切片输入因上下文缺失而可能进行流畅的编造，因此不同范围对同一对象给出矛盾结论是常态而非故障。确定性检查器具备同输入必同输出的特性，但生成式量具不具备该性质，导致前述确定性检测器相关条款中关于先测误报与同引擎基线对比的默认假设，对生成式量具并不适用。

**证据**：2 处疑似重复读取被整区间转写否定（幻觉率 2/2）；1 处真实碎音（−20dB 级，在阈值扫描中全盲）由同一输入路抓取；净版覆盖率 0.886 与 raw 同引擎基线 0.895 相比，缺口通过同路逐词对照证实为专有名词误听，并非内容损失。

**判据**：① 同一生成式量具对同一对象的两次输出产生矛盾时，⛔ 任何一次输出均不得作为裁决另一次的证据，必须改用独立第三路（不同输入范围／不同工具／物理测量）来定案；② 模型输出仅作线索不作判据，「检出／未检出」的结论必须明确注明是由哪一路输入方式所产生的；③ 裁决路径本身必须具备可复现性：本例中整区间孤立转写对两处嫌疑各运行一遍且均仅单次出现，才判定为幻觉。

**脱敏说明**：已剔除具体日期、产品名、特定业务场景及内部文档路径与章节号，保留的技术机制与通用数字不包含可反推特定项目或内部结构的敏感信息，属于通用的工程质量判据笔记。
