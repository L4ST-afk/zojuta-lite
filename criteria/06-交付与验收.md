# 06-交付与验收 · 完成分四层，预览通过不等于交付通过
> 本卷 7 条。判据集脱敏版：项目名、路径、内部编号已剥离；每条保留「问题／机制／证据／判据」四段与风险自评。

## 完成分四层，首次响应不抢定稿

<!-- 原编号 §2.21 · 脱敏风险 低 -->

**问题**：在交付与复用流程中，接口返回成功、列表填充、局部字段非空、模块检查通过，或查找与解析成功，都可能被直接表述为整轮完成或链路可用，导致完成范围超过实际验证范围。

**机制**：将完成证据分为四层：请求接受、完整持久化、内容正确、整轮项目齐全；四层不能互相替代。首次响应仅给出已核事实，并明确标记不可转发的框架内容。素材快照、词表覆盖和字符串相等均不等于来源认证或语义正确。声称链路可用时，至少要验证用户下一步的实际操作（构建、运行或交付），并且只报告已经验证的范围；打印路径或解析成功只能表述为“已找到/已解析”，不能表述为“可复用/已跑通”。复用被拒绝时，应单独核查拒绝出口。自检时需回答：声称“已打通”对应哪一层，用户下一步是否已经验证。出现查找成功但消费端拒绝、版本变化，或准备把局部成功改写为整轮完成时，应回看查找输出与真实消费端日志，不沿用旧有宣称。

**证据**：保存19项、入口13项、字段同步4项各自通过，仍不证明真实完整交付或英语正确。补充实测（在一次执行中，素材复用宣称被重建结果推翻）：查找返回 rc=0，并打印路径、sha 和重建命令；这曾被表述为“复用路径打通”。实际调用当前构建器后，核验的3个实际产物包中2个可构建、1个被拒绝，推翻了把查找成功当作复用成功的宣称。该例说明“能读到”只证明上一层，不证明“能用”。

**判据**：每次标记“完成”都必须写明完成对象以及四层中的具体层级；不得以接口 success、列表已填、三个字段非空或一个模块全绿结束整轮并宣称完成。声称链路可用时，至少要有用户下一步的实测证据，并明确实际验证范围；打印路径或解析成功只能表述为“已找到/已解析”，不能表述为“可复用/已跑通”。

**脱敏说明**：仅去除具体执行日期，其余小样本比值与判据逻辑均按规则保留，未引入占位符或新增结论。

## 修复合规测试夹具，不削弱原故障断言

<!-- 原编号 §2.23 · 脱敏风险 低 -->

**问题**：新增的校验规则会导致原有测试在达到目标阶段前被提前拦截，产生“已报错但并未实际完成测试”的虚假覆盖。

**机制**：通过补充合规的身份、数据素材与基准配置，促使故障场景能够顺利到达预期的测试阶段；随后捕获真实的报文构造正常回读，并进行定向变异，同时使用独立的预期值对报文进行校验，避免陷入循环自证。

**证据**：经过修复，四套测试用例从“一绿三红”的状态恢复为四套 rc0、stderr 0B 的正常状态；此前因手写回读遗漏 2 个默认字段导致了错误的失败判定。原有的字段丢失、旧值留存、网络中断等断言均被保留；针对静态异常处理的适配，也具备了实际写入前与写入后的异常行为证据。

**判据**：拒绝写入的断言记为 W0，写入后的故障断言记为 W1 且必须为非零值；必须证明测试流程确实到达了待测阶段，严禁通过删除高难度断言来换取测试通过。

**脱敏说明**：脱敏后内容均为通用的软件测试与接口校验场景描述，未包含任何特定业务名称、人员信息或内部路径，难以反推出具体的内部工程背景。

## 有界收口，旧示例与回退命令同步更新

<!-- 原编号 §2.27 · 脱敏风险 低 -->

**问题**：在变更冻结与收口阶段，需要界定已改动与未改动边界，防止用局部检查通过掩盖未完成项，或因无限制扩大核查范围而拖延交付；同时需在更新纪律时同步更新配套速查、示例、回退路径与完成说明。

**机制**：先确定范围、不可触碰项、通过矩阵、回滚点与停止条件；范围冻结后仅补齐已明确的缺口，新发现的问题另列处理。任何纪律变更都必须同步更新速查、示例、回退路径与完成话术，不能只强调优先处理主文件。在评估可逆排布试点时，不应把证据完整性当作最终结论，也不应把可逆的排布试点当作需要审批的发布。评估顺序应先选取最具代表性且最难通过的单元进行验证，通过后再推广；不预先设定原页数或每页块数的硬性限制。对历史失败项保留真实状态并判断其对当前路径的影响，既不一次性豁免，也不默认扩大为全量修复。

**证据**：独立审查发现3类可执行旧规则冲突，修复后6项文档检查通过；随后定向补充4项字段验证，而非扩展历史审计范围。离线批次完成收口，混合任务整轮耗时仍需补充证据。追加现场（近期，匿名长产物）中，反例表现为协调方连续要求修改汇总措辞、核查旧回归、重跑同一闸口，而剩余4个稀疏页仍原样保留；在要求更积极处理后，仅调整分组数组与预期页数，四块按序合排，执行方报告正文由三十余页缩减至不足三十页，gap由约三至四成降至一成左右。上述数字来自执行方报告与当件截图回读，并非本轮重新生成；不将像素阈值移植为通用门槛。

**判据**：明确区分已完成与未完成，并交付用户可访问的结果；不得用局部检查通过压制未完成项，也不得通过无限扩展审计拖延交付。对历史套件债务与本批次影响分开记账，未经实证不得豁免，也不得默认绑定为全量清债。先以最难代表单元验证，通过后再推广；不预设原页数或每页块数的硬限。历史失败项保留真实状态并判断当前路径影响，不一揽子豁免，也不默认扩大为全量修复。

**脱敏说明**：日期、页数及百分比范围已替换为相对量或量级表述，判据逻辑与机制说明未作改动，未引入新结论或占位符。

## 预览链路验证通过 ≠ 交付链路验证通过：出件前必须端到端复验

<!-- 原编号 §2.167 · 脱敏风险 低 -->

**问题**：渲染属性在屏幕上生效，不代表在最终出件（PDF／印刷／导出）里也生效。中间隔着另一套排版引擎。

**机制**：对两个 CSS 属性先在屏幕渲染引擎中进行验证，再通过打印转换工具生成 PDF 产物，并提取文本坐标进行交叉复验。版式断言须登记「布局源→填充/排版处理→打印驱动→最终 PDF→坐标提取器」及容差；DOM/HTML 仅作定位，不代替最终产物基线或墨迹坐标复测。对照矩阵明确区分有/无相关元素（如译文、折行、胶囊），缺元素的样本记不适用，不能冒充断言通过；动态填充需另验无/有填充两态。

**证据**：实测：两个 CSS 属性先在屏幕渲染引擎验证，再走打印转 PDF 及 PDF 坐标提取重验。屏幕端（DOM 边界矩形测量）text-autospace 为数像素级偏移（字号与偏移量呈约 1/8 em 的比例）；trim 折合 8/9/7 字。PDF 端（PDF 坐标提取）为数磅级偏移（字号与偏移量同样呈约 1/8 em 的比例，多处边界复核）；trim 折合 8/9/7 字，结果完全一致。

**判据**：① 凡是最终要出成某个格式的验证，必须在该格式的产物上再验一遍，不能只验预览，否则视为不合规；② 两链路数字对得上才算交叉印证；对不上则至少有一条链路的假设是错的，视为不合规；③ 报告里写清只验了哪条链路（本例：只验了浏览器打印转 PDF，其他排版引擎未测）；④ 版式断言须登记布局源到坐标提取器的全链路及容差；DOM/HTML 只作定位，不代替最终产物基线或墨迹坐标复测。对照矩阵明确区分有或无相关元素，缺元素的样本记不适用，不能冒充断言通过；动态填充另验无或有填充两态。与对照实验同源同环境的条目呼应：本条是它的下游，同源还不够，还要同交付链路。

**脱敏说明**：仅替换了精确测量读数与日期，保留了核心比例关系与小样本字数证据，判据逻辑与机制说明完整未变。

## 快照文档必须标注时效免责声明

<!-- 原编号 §2.285 · 脱敏风险 低 -->

**问题**：参考文档中的行数、覆盖区间和质量状态（如数百行、单日覆盖区间、ok）看起来像实时值，实际是某次实测快照，会随服务端发布而漂移。如果将静态快照误认为实时状态，后续数据因发布而变化时便会出现不一致，进而造成信任破裂。

**机制**：任何带时间戳、行数、覆盖区间或质量状态的参考文档，默认都是快照，而不是实时数据源。文档顶部必须注明数据来源、采集时点和失效判据；内容会随外部系统变化时，必须明确写明「以当次数据读取为准，本页不保证实时」。

**证据**：一次实测显示：相关参考文档顶部增加了免责声明，明确行数、覆盖区间和质量状态是某次实测快照，会随服务端发布变化；以当次数据读取和时效检查结果为准，本页不保证实时。示例数据包含数百行、覆盖区间为单日，质量状态为 ok。

**判据**：① 参考文档若含行数、覆盖区间、质量状态等可变数值，顶部必须同时注明采集时点，并声明以当次接口读取为准；② 快照数字不得作为判断「当前状态」的唯一证据，判断「有没有数据」必须依据当次数据读取及时效检查结果。缺少任一项即不符合要求。

**脱敏说明**：删除的均为具体日期与精确行数等来源指纹，已替换为相对量表述，机制、判据句和边界说明逻辑未做任何改动。

## 测试桩要覆盖协议完整生命周期，状态不可混用

<!-- 原编号 §2.287 · 脱敏风险 低 -->

**问题**：在自动化测试的 HTTP 桩中，初始化方法原本落入返回预设数据集的分支（虽能运行但语义不清晰），掩盖了真实调用时的顺序依赖问题（必须先完成初始化才能调用工具）。

**机制**：模拟服务与测试桩若仅实现“能返回数据”而不遵循协议状态机，将掩盖真实调用时的顺序依赖。测试桩必须覆盖协议的完整生命周期（initialize → initialized → call → ...），且各状态不可混用。

**证据**：测试桩新增 initialize 单独返回包含 capabilities 字段的空对象，随后处理 notifications/initialized，再返回固定数据集；自动化自测 14/14 通过，变异测试撤销两处修复导致 4 条用例失败。

**判据**：① 测试桩对协议的每个阶段有独立返回（initialize 返回 capabilities，initialized 返回 202，call 返回业务数据）；② 变异测试：撤销任一修复，对应用例必须失败；③ 测试桩返回结构必须与真实服务同形（JSON-RPC 2.0、`data: ` SSE 行等）。

**脱敏说明**：已去除特定的脚本名、项目名及内部路径，内容转化为通用的接口测试桩设计规范，不含可反推具体业务或内部环境的敏感信息。

## 凭据纪律贯穿全链路，体检器做值形判真不误伤正常代码

<!-- 原编号 §2.288 · 脱敏风险 低 -->

**问题**：在工具调用与自检流程中，直接调用时的网络异常可能抛出未处理异常，导致退出码不规范；凭据检测逻辑可能将正常代码中的凭据处理语句误判为凭据，造成自检流程卡死；失败回执可能将凭据前二十余字符打印到标准输出。

**机制**：凭据安全不仅限于不写入文档，自检器或体检器本身也不得将凭据前缀输出到标准输出或回执。检测逻辑必须执行“值形判真”：代码中的凭据变量赋值不等于真实凭据泄露；裸标识需同时包含字母和数字才可能为真实凭据；代码调用、模板占位及假值（fake、dummy、example、test-token）不视为凭据。证据仅记录文件名与行号，不记录任何凭据值。

**证据**：实测记录显示：保存流程正常，落盘权限为 600，明文不回显；凭据识别误报修复后，一批数处正常代码不再被误报；凭据前缀不进入标准输出或回执。

**判据**：①凭据仅通过标准输入传入，不写入命令行参数；②落盘时立即设置权限为 600，先以指定权限打开文件再写入，避免先写后改权限的窗口期；③任何模式均不打印凭据值，仅打印来源路径与掩码；④体检器对凭据识别必须执行值形判真，不得误伤正常代码；⑤回执与标准输出仅记录文件名与行号，不记录凭据值。

**脱敏说明**：已清除具体日期、精确字符数与精确计数等读数指纹，判据逻辑、机制描述与边界说明完整保留，无残留可定位信息。
