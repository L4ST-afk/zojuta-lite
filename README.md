# 禅院塔·籁（Zojuta Lite）· 判据集

**一套可以拿来审自己工程的判据。不给你答案，给你该问的问题。**

> 六面七层，青砖嶙峋。昔年檐廊回廊，一旦尽撤，塔遂中空无顶；然巅上一榕，不借寸土，根垂塔腹，迎风自茂，反以榕荫为冠。遂取以为法：溯其由、征其测，判当下之合规；不饰虚声，不立次第，所载皆易地犹立之理。

本集是**禅院塔（Zojuta）主库的判据层**，2026-11-24 快照，17 卷 98 条。

禅院塔是一座通用工程工作法母塔，名字取自温州江心屿东塔——那座塔的檐廊被拆光了，只剩骨架，巅上一棵榕树替它成了顶。判据层继承的就是这个骨架：只留「什么问题值得问」，不留排场。

主库未开源。这里只放判据本身：什么问题值得问、问到什么程度算问清了。运行层（闸门实现、自检脚本、目录治理、发布流程）留在主库，不在本仓。

## 〇、这是什么，不是什么

**是**：98 条判据，每条都能回答一个问题——「我这次算不算违规」。

**不是**：清单、模板、最佳实践合集。

这个区别值得说清，因为它决定了你怎么用。

模板给你一个音，你照着吹。判据给你一个问法，你自己吹。凡是需要按项目实际情况定阈值、定口径的地方，本集一律只给「怎么定」，不给「定成多少」——不是留白偷懒，是立场。同一套判据落到不同工程上，结论本来就该不同。

所以你会看到很多这样的句子：

- 「下限必须从实际执行结果反推，不能从文档抄」——而不是「下限设成 50」
- 「红与不红只取决于『余量 − 增量』是否为负，与绝对体量无关」——而不是「余量留 5%」
- 「判定『没有』必须由响应内容本身证明，而不是由请求参数支撑」——而不是「查三次」

数字在证据段里，不在判据段里。这是故意的：判据段要能跨项目成立，数字只在它诞生的那个现场成立。

## 一、禅院塔是什么

「禅院塔」不是一座抽象的塔，是**温州江心屿东塔**——一座能指认的实体。名字里的每个意象都能落回判据：

| 实体（可核） | 落到判据上 |
|---|---|
| 建于**唐咸通十年（869）**，早于西塔 | 判**过程**的塔先起：过程判据在做的当口就要立，不能等做完再补 |
| 塔檐、回廊被**英方强令拆除**，今中空无顶 | 判据被外部砍掉装饰后仍要成立：只管骨架（做了什么、按没按顺序），⛔ 不管排场 |
| 塔顶**榕树成荫**，无檐却「绿荫成顶」 | 缺的部分可由既有经验补位：判据缺项时用通用经验补，不新造规则 |
| 六面七层，**逐层可点** | 过程可逐段核：一单一核，不靠整体印象 |
| 与西塔**同作航标**八百余年 | 判据要能给别人导航：可读性优先于完备性，别人看得懂才叫合规 |

塔分东西两座，判的是两件事：**东塔判「这一步做对了吗」**（当下、逐段、可复核），**西塔判「这个人真的变了吗」**（隔期、点数、需证据账）。合成一座，就会拿过程合规去替结果达成结账——这是主库明写的反例。

拉丁槽 `Zojuta` 与西塔 `Quojuta` 共尾 `-juta`，靠首段 `Zo-` 分辨。`Zo` 取苏州音「禅」`zoe`（温州音 `ji` 拼成 `Jijuta` 会 `j-j` 连缀），后两段走温州音：`ju` 是院 `jy`，`ta` 是塔 `tʰa`。这是主库唯一一件跨点取音，理由写死在主库定名卷里。

## 二、为什么叫「籁」

「籁」出自《庄子·齐物论》。子綦讲完地籁、人籁，子游问天籁，答：

> 夫吹万不同，而使其自己也，咸其自取，怒者其谁邪！

风吹过万千孔窍，声音各个不同，但没有一个外在的东西在替它们定音——每个孔窍按自己的形状发声，声音是它自己取的。这就是天籁。

拿它给判据集命名，取的就是这个意思：**判据不替你的项目定标准，只让你按自己项目的形状，把该问的问题问出来。**

`Lite` 说的是「只留判据层」这个减法，不是说它简陋。`Zojuta` 原样保留，只加后缀——主库的拉丁槽与姊妹库共尾 `-juta`，拆族尾会让双塔不再成对。

**⚠️ 两套意象不焊**：「禅院塔」的意象落在东塔实体，逐条能指认；「籁」走的是典籍义（《庄子·齐物论》天籁），不走实体意象。两者不构成同一套意象系统。⛔ 不得写成「籁是塔上的声音」这类把两套意象硬焊的话——主库定名卷把这条列为诚实缺口。

## 三、怎么读一条判据

每条都是四段式，缺一段就不收：

| 段 | 回答什么 |
|---|---|
| **问题** | 什么情况下会出事 |
| **机制** | 为什么会出事，出事的路径是什么 |
| **证据** | 谁在什么条件下实测过，读数是多少 |
| **判据** | 你这次算不算违规，怎么判 |

举个完整的例子（`02a-断言记账.md` 第一条）：

> **问题**：当执行计数与验收转录来自同一推导来源时，即使删除断言并同步篡改转录，校验仍可能显示通过。
>
> **机制**：分别设置两个独立的下限观测值：执行计数下限与静态 AST 调用点下限，后者覆盖平时不执行的防御分支；两个下限只允许上调、不允许下调。
>
> **证据**：另一次变异同时删掉一条断言并改动转录，执行数比下限低一、调用点数比下限低一，因此仍被判不通过。
>
> **判据**：若删除一条断言并同步修改转录后仍能通过校验，则本次判定违规；比较对象必须是独立设置的下限，而不是被测物自行上报的数值。

注意判据段最后半句——「比较对象必须是独立设置的下限」。这就是它能回答「我算不算违规」的原因：它给了一个可操作的比较，不是一个形容词。

**用法**：不要从头读。带着你手上正在做的事去找——你刚写完一个闸门，去 `02b`；你在对账，去 `01b`；你在验收交付，去 `06`。找到那条，读它的判据段，问自己「我这次算不算违规」。

## 五、这些判据是怎么来的

不是想出来的，是踩出来的。

每条的「证据」段都是一次真实的翻车：闸门绿着但东西是坏的、对账对上了但两边抄的是同一份、自检说就绪但根本没跑、交付说完成但用户打不开。这些判据是那些事故留下的疤。

所以它们有一个共同特征：**都指向「看起来对了但其实没对」**。这是这套东西真正的主题。如果你只记一句，记这句——绿了不等于对了。
